# Capabilities by runtime

Generated by `scripts/lib/capabilities.mjs` (`node scripts/cli.mjs capabilities --write`). Do not edit by hand.

`builtin` is the engine and the oracle: always `✅`. ✅ same · ◐ partial, the rest declined · ✖ not supported, and declared · ⚠ **different without a warning** (what still has to be closed).

The `msw` cells are checked in `tests/parity.test.mjs` (fast, with a stub that runs the handlers) and in `tests/parity-real.test.mjs` (real `msw/node`, `ATREZZO_PARITY=real`, nightly). A cell without a test is a promise.

## Why each cell is not ✅

- **filters × supabase** (different): PostgREST compares with its own types: `null` and lists do not behave the same
- **filters × prism** (not supported (declared)): does not evaluate filters: it returns the example from the spec
- **filters × wiremock** (partial): one value per filter; other combinations end in 501
- **pgrst-operators × prism** (not supported (declared)): does not evaluate operators
- **pgrst-operators × wiremock** (partial): one operator per mapping; the rest end in 501
- **pagination × supabase** (different): PostgREST pages with `Range`; the `limit` in the query is not the same cut
- **pagination × prism** (not supported (declared)): ignores the pagination parameters
- **pagination × wiremock** (partial): only the pages listed in the flows; the rest end in 501
- **sorts × supabase** (different): PostgREST sorts in SQL: nulls and `nullsfirst` do not land where they land here
- **sorts × prism** (different): declares the parameter and ignores it: the order is the example's
- **sorts × wiremock** (partial): only the requests that appear in the flows
- **scopes × supabase** (different): the filter has to exist in the view; otherwise PostgREST answers with its own error
- **scopes × prism** (different): does not evaluate the parameter
- **scopes × wiremock** (partial): one value per scope
- **envelope × supabase** (different): PostgREST decides the shape (an array or `{data,count}`), not the envelope
- **envelope × prism** (different): the OpenAPI schema does not declare `total_pages`: only the example carries it, so dynamic mode (`-d`) and schema validation leave it out
- **singleton × supabase** (different): `.single()` needs `Accept: application/vnd.pgrst.object+json`
- **singleton × prism** (partial): always returns the first row of the example
- **relations × supabase** (different): the embed has to be a real foreign key, and the projection is requested differently
- **nested-routes × supabase** (different): each segment is a table or a view
- **nested-routes × prism** (different): the example is the projection for the first row's values: any other parameter value gets the same rows
- **nested-routes × wiremock** (different): no mapping is generated for routes with path parameters unless they declare `error` or `passthrough` (only a note at generation time): they answer 404
- **world-filters × supabase** (different): the per-user filter comes from RLS, not from the scenario
- **writes × supabase** (different): writes for real to Postgres: resetting the world does not undo them
- **writes × prism** (different): the write routes are not emitted and there is no 501: they answer 404
- **writes × wiremock** (different): the write routes are not emitted and there is no 501: they answer 404
- **rpc × supabase** (different): the function has to exist in Postgres; the scenario does not create it
- **rpc × prism** (different): the endpoint is not emitted and there is no 501: it answers 404
- **rpc × wiremock** (different): the endpoint is not emitted and there is no 501: it answers 404
- **streams × msw** (not supported (declared)): an explicit 501 on the stream route: the flow sees the warning, not the events
- **streams × supabase** (different): PostgREST has no SSE
- **streams × prism** (different): the endpoint is not emitted and there is no 501: it answers 404
- **streams × wiremock** (different): the endpoint is not emitted and there is no 501: it answers 404
- **passthrough-error × supabase** (different): the adapter only emits SQL: neither the recorded fixture nor the declared error reaches PostgREST
- **latency × supabase** (different): the latency is whatever Postgres takes
- **latency × prism** (different): does not apply `latency`
- **latency × wiremock** (different): has `fixedDelayMilliseconds`, but the generated mappings do not use it
- **diagnostic-headers × supabase** (not supported (declared)): PostgREST sets the headers (`Content-Range`)
- **diagnostic-headers × prism** (partial): only the example's total, no `X-Atrezzo-Ignored`
- **diagnostic-headers × wiremock** (partial): the total, yes; `X-Atrezzo-Ignored`, no
